# CHANGELOG Entry Template

Use this template when creating a new changelog entry. Replace all `[...]` sections with actual content.

```markdown
# [Version] - [YYYY-MM-DD]

## Added

### Core Features
- [Feature description and impact]
- [Feature description and impact]

### CLI Tool
- [CLI feature or improvement]
- [CLI feature or improvement]

### VS Code Extension
- [Extension feature or improvement]
- [Extension feature or improvement]

### Documentation
- [New or updated documentation]
- [New or updated documentation]

### Developer Experience
- [Tooling, setup, or DX improvement]
- [Tooling, setup, or DX improvement]

## Changed

- [Breaking or significant change with rationale]
- [Behavior change with explanation]

## Fixed

- [Bug fix with description]
- [Bug fix with description]

## Deprecated

- [Deprecated feature with migration path]
- [Deprecated feature with migration path]

## Technical Details

### Architecture Improvements
- [Architectural change or refactor]
- [Architectural change or refactor]

### Testing
- [Test coverage additions]
- [Test improvements]

### Type Safety
- [Type improvements or fixes]

## Migration Guide

If there are breaking changes, include:

### For Users
[Step-by-step migration instructions]

### For Contributors
[Development environment changes needed]

## Notes

- [Important context or rationale]
- [Links to related issues or discussions]
```

## Guidelines

- **Versioning**: Follow [Semantic Versioning](https://semver.org/)
- **Format**: Use present tense ("Add feature" not "Added feature")
- **Scope**: Focus on user-facing changes and significant technical improvements
- **Links**: Include issue/PR numbers like `#123` when relevant
- **Audience**: Write for both end users and developers
- **Completeness**: Include all meaningful changes since last release
